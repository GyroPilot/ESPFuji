ESPFuji 1.1.4 is the current version. If your ESProFile runs ESPFuji 1.1.3 or earlier, please update. 1.1.3 fixed the fault that lost bytes while the drive's Wi-Fi was busy; 1.1.4 adds a guard for poor cables and faulty boards. What was wrong and what changed is explained below.

Not supported: starting the Lisa from an external ESProFile on a parallel card. What was wrong, and what 1.1.3 and 1.1.4 change

With ESPFuji 1.1.2 and earlier, the ESProFile could occasionally lose a byte of a block while its own Wi-Fi was sending. A block written by the Lisa could then be stored a byte short, and the Lisa was not told, so the damage showed up later. On one Lisa 2/10 it made the startup disk unusable ("You have no environments on the startup disk"). This was a fault of ESPFuji, not of Alex's ESProFile firmware.

ESPFuji 1.1.3 keeps the network side of the ESP32 still for the length of every disk transfer, so the radio can no longer disturb the disk. It also refuses a block that does not arrive complete, so the Lisa repeats the write instead of the drive storing a damaged one. The drive now counts what it sees: in the ESPFuji tool on the Lisa, S shows the counters ("refused" and "odd" should stay at 0).

Tested before release: more than 120,000 block transfers on a test bench with the radio busy, a Lisa 2/10 through a working session with a network game and a restart, and a Macintosh XL through two half-hour tests that wrote and compared every byte. No lost byte in any of them.

ESPFuji 1.1.4 closes one smaller weakness that 1.1.3 still had: on a poor cable or a faulty board a control line can glitch, and a block could then be read one byte short. In 1.1.4 such a glitch no longer ends the drive's protection for the block being transferred, and a write whose command arrived damaged is refused, so the Lisa repeats it. Everything else is 1.1.3.

Tested before release: on a bench (one ESProFile reading and writing another, with worst-case data and heavy Wi-Fi traffic) more than 700,000 block transfers, none short and none refused, where the same bench shows short reads with 1.1.3; a Lisa 2/10 with an internal ESProFile through a cold start and a session with a network game; a Macintosh XL through Drive Test XL; and an external ESProFile on its cable as a second disk of a Lisa 2/10, with a tool copied onto it and compared byte for byte.

You can check your own drive: in its STATUS line (S in the ESPFuji tool on a Lisa; Drive Status in ESPFuji XL 1.1, or Drive Test XL, on a Macintosh XL) odd and refused should be 0, and timeouts should be no higher than init (a Lisa makes one or two of those at every start).

If you used ESPFuji 1.1.2 or earlier

  • Update to 1.1.4 with the button above.
  • A disk that was written to under an older ESPFuji may hold a damaged block. If you have a backup of the disk image from before, keep it. If the Lisa reports a damaged disk, repair it from the Office System 1 diskette or go back to your backup.
  • From now on, back up your SD card now and then (copy the disk image to a computer).

Use a good USB cable. This matters more than anything else on this page. The installer sends four megabytes over the cable, and a worn, very long or charge-only cable can drop data partway through. The install then stops, or the ESP32 is left half-written and will not start, and the Lisa cannot see the ESProFile. Use a short cable that you know carries data (one you have used to copy files, not just to charge), and plug it straight into the computer: no hubs, extension cables, keyboard or monitor ports. If anything goes wrong, change the cable first, then run the install again.

Before you start

  • A computer with Chrome or Edge.
  • A good, short USB data cable (see above; some phone cables only charge).
  • The ESProFile's ESP32 board, either the external ESProFile or the internal one inside the Lisa.

For an ESP32 that already works in an ESProFile (updating from Alex's firmware or an older ESPFuji). A brand-new ESP32 first needs Alex's one-time flash-voltage step (espefuse set_flash_voltage 3.3V, in the ESProFile README), which a web page cannot do. Without it the board will not start on the ESProFile.

Turn the Lisa (or Mac XL) OFF first. The USB cable alone powers the ESP32 while it is being updated. The Lisa must not be powering it at the same time.

Steps

  1. Turn the Lisa off.
  2. Plug the USB cable into the ESP32 board on the ESProFile and into the computer.
  3. Click Install ESPFuji 1.1.4 above.
  4. A list of ports appears. Pick the one that appeared when you plugged the cable in (often named CP210x, USB Serial or usbserial) and click Connect.
  5. Click Install. The installer then asks you to confirm and says "All data on the device will be erased": that means the ESP32's own firmware only. The SD card, your disk image and espfuji.ini are not touched. Click Install again and wait until it says the installation is complete (about two minutes). Do not unplug the cable while it is writing.
  6. Unplug the USB cable, put the SD card back if you took it out, and start the Lisa. Your Lisa programs work as before; ESPFuji's HELLO now answers ESPFuji 1.1.4. Wi-Fi joins about a minute after power-up, or as soon as a Lisa program asks for the network.

If something goes wrong

  • No port in the list: try another cable (some only charge), or install the USB driver for the board's chip: Silicon Labs CP210x. Then reload this page. (Recent Macs need no driver: the port shows as CP2102 USB to UART Bridge Controller (cu.usbserial-…).)
  • It fails partway (for example "Invalid head of packet") or sits on "Connecting": close the installer, unplug the USB cable, plug it back in and click Install again. A failed try does no harm: the ESP32 simply needs the install run again before it will start. Plug the cable straight into the computer, not into a hub, keyboard or monitor. If it still fails, use the command-line method: flash_espfuji_release.py from the release page.
  • The list of ports closes before you can pick one, or the port is "in use": close every other tab that has this installer open (and any serial monitor), then click Install again.
  • Still stuck on "Connecting"? Put the ESP32 into update mode by hand: it has two small buttons beside its USB socket, BOOT and EN (or RST). While the installer shows "Connecting", hold BOOT, tap EN, then let go of BOOT.
  • The Lisa shows error 85 after the update (or the ESProFile's light stays off or red): the ESProFile is not answering the Lisa. Usually the install did not finish. Turn the Lisa off, use a better cable plugged straight into the computer, and run the install again until it says the installation is complete. Then check that the SD card is pushed fully in and that the board's small switch is on its emulator side; an external ESProFile should be powered up before the Lisa. Error 85 when you start the Lisa from an external ESProFile on a parallel card is something else: ESPFuji does not support that (see the note at the top of this page). Start the Lisa from its internal disk.
  • Want a backup of the old firmware first? This page cannot make one. The command-line script can: flash_espfuji_release.py backup, and its restore puts the saved firmware back at any time.
  • The installer says there is no firmware for this chip: this page installs on the plain ESP32 that the ESProFile boards carry. The fixes in 1.1.3 and 1.1.4 are for that chip. An ESP32-S3 build is on the release page for testers only: it has never run on hardware and does not have the main fix yet.

Going back to Alex's stock firmware

With the stock firmware the ESProFile is a disk for the Lisa exactly as Alex made it. The Lisa programs that use the network through ESPFuji (LisaFuji, the Browser and the others) will not reach the network until ESPFuji is put back. Your disk image stays as it is, and espfuji.ini can stay on the SD card: the stock firmware ignores it. The steps are the same as above (Lisa off, good cable, wait for "installation complete").
